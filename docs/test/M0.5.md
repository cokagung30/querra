## Konteks untuk Claude

- Sejak 14 November 2026 Smart App Control di PC Windows uji memblokir build Querra tanpa tanda tangan, termasuk build CI dan Querra hasil instalasi NSIS 8 November (PLAN R10, `docs/spikes/fase-0.md` §4.7). Keputusannya: Windows didistribusikan lewat Microsoft Store sebagai MSIX yang ditandatangani Microsoft (PLAN §8.1). Spike ini membuktikan jalur itu.
- Paket: `querra-amd64.msix` dari artifact CI `querra-windows`, identitas `BaliDigitalKarya.Querra` (manifest di `build/windows/msix/app_manifest.xml`). Submission pertama memakai **private audience**: hanya grup "Querra Tester" (akun Microsoft pribadi pemilik) yang bisa memasangnya, lewat tautan privat `https://apps.microsoft.com/detail/restricted/9N741TW7R6PF`. Isian listing, alasan `runFullTrust`, dan catatan untuk tester sertifikasi ada di Partner Center. Kebijakan privasinya `PRIVACY.md`.
- Build ini baru berisi shell M0.3. `internal/store` dan `internal/secrets` belum dipasang ke `main.go` (M1.3 yang memasangnya), jadi build ini tidak membuat `querra.db` dan tidak menulis ke Credential Manager. Cek container untuk keduanya (D3, D4) dipindah ke PLAN M1.4, ke build Store pertama yang punya UI koneksi. Satu-satunya data yang ditulis build ini adalah profil WebView2 (ukuran panel tersimpan di `localStorage`).
- Status bar akan menampilkan `v0.1.0-dev`, karena `main.version` baru diisi lewat `-ldflags` di workflow rilis (M4.6). Ini sudah diketahui, bukan kegagalan.
- Setelah submission 1 terbit, Partner Center menampilkan draft *Product update* (Submission 2) yang semua bagiannya *Unchanged*. Draft itu tidak mengubah versi yang sudah terbit. Jangan dikirim sebelum ada MSIX baru dengan `Identity/@Version` lebih tinggi (mis. build Store pertama dengan UI koneksi, M1.4): unggah paket itu di draft ini, lalu **Submit for certification**.
- **Selesai 14 November 2026.** Hasilnya tercatat di `docs/spikes/fase-0.md` §4.7 dan kolom Windows `M0.3.md`, dan M0.5 sudah dicentang di PLAN. Peluncuran diverifikasi dari log `Microsoft-Windows-AppModel-Runtime/Admin` (event 201 "Created process … Querra"), dan blokir dicari di log `Microsoft-Windows-CodeIntegrity/Operational`. Cara ini bisa dipakai lagi tanpa screenshot.

## Persiapan

*Status 14 November 2026: ketiga langkah persiapan sudah beres. Querra NSIS sudah tidak terpasang (tidak ada entri uninstall, folder program, maupun shortcut Start menu), dan Claude sudah mengganti nama `%AppData%\querra.exe` menjadi `querra.exe.nsis-old`.*

1. Tunggu email dari Partner Center bahwa sertifikasi lulus dan aplikasi sudah terbit. Kalau gagal, tempel alasan penolakannya ke Claude dan catat di **Temuan**.
2. Hapus dulu Querra lama (NSIS, 8 November) supaya tidak ada dua entri "Querra" di Start menu: **Settings → Apps → Installed apps → Querra → Uninstall**. Kalau uninstaller-nya diblokir Smart App Control, catat di **Temuan** dan lanjutkan. Di B3, buka versi Store lewat tombol **Open** di aplikasi Microsoft Store, karena di Start menu kedua entri sama-sama bernama "Querra".
3. Ganti nama folder data WebView2 lama `%AppData%\querra.exe` menjadi `querra.exe.nsis-old` lewat File Explorer. Tujuannya agar versi Store mulai dari kondisi bersih dan lokasi datanya jelas di D1. Folder itu boleh dihapus setelah M0.5 selesai.

## Temuan

<!-- Satu butir per masalah: ID langkah, platform, apa yang terjadi, dan tindak lanjutnya. -->

- **D1/D2, Windows (informasi, bukan masalah):** Package family name-nya `BaliDigitalKarya.Querra_m596njqrn6kpj`. Data aplikasi ada di `%LocalAppData%\Packages\BaliDigitalKarya.Querra_m596njqrn6kpj\`, dan tulisan ke `%AppData%` dialihkan ke `LocalCache\Roaming\` di dalamnya. Jadi `querra.db` dari M1.3 (`store.DefaultPath()` di bawah `%AppData%\Querra`) akan berada di `…\LocalCache\Roaming\Querra\querra.db`. Pengguna yang membuka `%AppData%\Querra` lewat File Explorer tidak akan menemukannya di sana.
