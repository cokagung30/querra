## Konteks untuk Claude

- **Sudah dibuat di Windows (lapisan domain):**
  - `internal/connection`: model `Settings`/`Connection`/`Group`, validasi (`FieldError` yang membungkus `ErrInvalid`), `Service` (CRUD, duplikasi beserta rahasianya, grup, `Arrange`), Test Connection bertahap (`probe.go`), ekspor/impor JSON (`transfer.go`), dan `Engines()`.
  - `internal/apperr`: kode §3.9 untuk M1.3, `From`, `FromConnect`, dan `Marshal`. Ada tes yang memastikan setiap kode punya terjemahan `errors.<code>` di `frontend/src/i18n/en.json`.
  - `internal/driver`: `DefaultPort()`, `Conn.ServerInfo`, penanda error (`errors.go`, `Mark`). Adapter PostgreSQL memakai keduanya.
  - `internal/store`: kolom `password_state` (migrasi `0002`), `Connections.Arrange`, `Groups.Arrange`.
  - Keputusan pemilik ada di PLAN M1.3.
- **Belum diverifikasi:** tes Go untuk semua kode di atas baru diperiksa dengan `go vet` (termasuk `-tags integration`) dan `go build`, karena PC Windows tidak bisa menjalankan biner tes. Hasil pertamanya datang dari CI setelah push. Kalau CI merah, perbaiki dulu sebelum mengerjakan lapisan Wails.
- **Yang dikerjakan di Mac (butir terakhir M1.3 di PLAN):**
  1. `internal/app/connectionservice.go`: `ConnectionService` yang tipis. Method-nya meneruskan ke `connection.Service` (`List`, `Get`, `Create`, `Update`, `Delete`, `Duplicate`, `Arrange`, `Groups`, `CreateGroup`, `RenameGroup`, `DeleteGroup`, `ArrangeGroups`, `Test`, `Export`, `Import`, `Engines`), dengan `ctx` sebagai argumen pertama bila menyentuh store atau database.
  2. Pemetaan error di service: `connection.ErrInvalidFile` → `apperr.InvalidFile`, `connection.ErrInvalid` → `apperr.InvalidInput` (Detail = `FieldError.Field`), `connection.ErrNotFound` → `apperr.NotFound`, lalu sisanya lewat `apperr.From`. Pasang `apperr.Marshal` sebagai `MarshalError` di `application.Options`, sehingga semua service mengirim `*apperr.Error`.
  3. `main.go`: buka store di `store.DefaultPath()` dan `secrets.NewKeyring()`, impor `_ "github.com/cokagung30/querra/internal/driver/postgres"`, lalu tutup store di `ServiceShutdown` (tanpa ctx). Kalau store gagal dibuka, tampilkan error, jangan crash diam-diam.
  4. `Export` mengembalikan `[]byte`. Cara frontend menyimpannya ke file (dialog Wails atau unduhan dari webview) diputuskan bersama UI di M1.4.
  5. `wails3 task bindings`, commit hasil generate, lalu `wails3 task lint` dan `wails3 task test`.
- Setelah lapisan Wails selesai, build Store berikutnya bisa menjalankan cek `querra.db` dan Credential Manager di MSIX (`M0.5.md` D3–D4).

## Persiapan (macOS)

```bash
git pull
cd frontend && npm ci && cd ..
wails3 task db:reset   # querra_test di PostgreSQL lokal (dev/test.env)
```
