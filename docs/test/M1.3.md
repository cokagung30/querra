## Konteks untuk Claude

- **Sudah dibuat di Windows (lapisan domain):**
  - `internal/connection`: model `Settings`/`Connection`/`Group`, validasi (`FieldError` yang membungkus `ErrInvalid`), `Service` (CRUD, duplikasi beserta rahasianya, grup, `Arrange`), Test Connection bertahap (`probe.go`), ekspor/impor JSON (`transfer.go`), dan `Engines()`.
  - `internal/apperr`: kode §3.9 untuk M1.3, `From`, `FromConnect`, dan `Marshal`. Ada tes yang memastikan setiap kode punya terjemahan `errors.<code>` di `frontend/src/i18n/en.json`.
  - `internal/driver`: `DefaultPort()`, `Conn.ServerInfo`, penanda error (`errors.go`, `Mark`). Adapter PostgreSQL memakai keduanya.
  - `internal/store`: kolom `password_state` (migrasi `0002`), `Connections.Arrange`, `Groups.Arrange`.
  - Keputusan pemilik ada di PLAN M1.3.
- **CI:** lapisan domain hijau di ketiga job (`macos-latest`, `windows-latest`, `integration (ubuntu)`) pada commit `8e62572`, run 43601756063. Commit `641def1` sebelumnya merah hanya karena lint (lihat **Temuan**).
- **Sudah dibuat di Mac (lapisan Wails, 22 November 2026):** `internal/app/connectionservice.go` (+ tes), `apperr.WithDetail`, `main.go`, dan binding di `frontend/bindings/.../internal/{app,apperr,connection,driver}`. Perbedaan dari rencana di bawah:
  - `MarshalError` dipasang per service lewat helper `service()` di `main.go`, karena Wails v3.1.0 tidak pernah memanggil `application.Options.MarshalError` (lihat **Temuan**). Opsi global tetap diisi, sesuai dokumentasi Wails.
  - `invalid_input` membawa nama field di `detail` dan alasannya (bahasa Inggris) di `message`.
  - Kalau store gagal dibuka, Querra tidak membuka jendela, menampilkan dialog error native berisi path `querra.db`, lalu keluar setelah OK.
  - Di TypeScript, `Export`/`Import` memakai string base64 (`[]byte` dari Go).
- **Selesai:** CI untuk commit lapisan Wails hijau di ketiga job (commit `8372fbd`, [run 45002233292](https://github.com/cokagung30/querra/actions/runs/45002233292)), termasuk lint dan cek binding basi di job macOS. M1.3 sudah dicentang di `PLAN.md`.
- **Rencana awal untuk Mac (butir terakhir M1.3 di PLAN), sudah dikerjakan:**
  1. `internal/app/connectionservice.go`: `ConnectionService` yang tipis. Method-nya meneruskan ke `connection.Service` (`List`, `Get`, `Create`, `Update`, `Delete`, `Duplicate`, `Arrange`, `Groups`, `CreateGroup`, `RenameGroup`, `DeleteGroup`, `ArrangeGroups`, `Test`, `Export`, `Import`, `Engines`), dengan `ctx` sebagai argumen pertama bila menyentuh store atau database.
  2. Pemetaan error di service: `connection.ErrInvalidFile` → `apperr.InvalidFile`, `connection.ErrInvalid` → `apperr.InvalidInput` (Detail = `FieldError.Field`), `connection.ErrNotFound` → `apperr.NotFound`, lalu sisanya lewat `apperr.From`. Pasang `apperr.Marshal` sebagai `MarshalError` di `application.Options`, sehingga semua service mengirim `*apperr.Error`.
  3. `main.go`: buka store di `store.DefaultPath()` dan `secrets.NewKeyring()`, impor `_ "github.com/cokagung30/querra/internal/driver/postgres"`, lalu tutup store di `ServiceShutdown` (tanpa ctx). Kalau store gagal dibuka, tampilkan error, jangan crash diam-diam.
  4. `Export` mengembalikan `[]byte`. Cara frontend menyimpannya ke file (dialog Wails atau unduhan dari webview) diputuskan bersama UI di M1.4.
  5. `wails3 task bindings`, commit hasil generate, lalu `wails3 task lint` dan `wails3 task test`.
- Cek `querra.db` dan Credential Manager di dalam container MSIX (dulu `M0.5.md` D3–D4) dipindah ke M1.4. Build Store yang hanya berisi M1.3 belum bisa menyimpan password lewat UI.

## Temuan

<!-- Satu butir per masalah: ID langkah, platform, apa yang terjadi, dan tindak lanjutnya. -->

- **A1, CI macOS (14 November 2026):** golangci-lint menolak nama variabel error `keychain` di `internal/connection/connection_test.go` (ST1012: harus `errFoo`). Lint ini tidak bisa jalan di PC Windows karena Smart App Control. Sudah diganti menjadi `errKeychain`; CI `8e62572` hijau.
- **B6, macOS (22 November 2026):** di Wails v3.1.0, `application.Options.MarshalError` disimpan tetapi tidak pernah dipanggil. `Bindings.Add` hanya menggabungkan `ServiceOptions.MarshalError` dengan marshaler bawaan (`pkg/application/bindings.go`). Kalau hanya opsi global yang diisi, error selain `*apperr.Error` sampai di frontend sebagai `{}`. Tindak lanjut: `main.go` mendaftarkan semua service lewat `service()`, yang mengisi `ServiceOptions.MarshalError`; dicatat di `CLAUDE.md`.
- **A4/B4, macOS (22 November 2026):** PostgreSQL 18.2 lokal memakai `trust` untuk koneksi TCP lokal, jadi password apa pun diterima. Bagian password salah di `TestOpenMarksLoginErrors`, `TestOpenWrongPasswordKeepsItOutOfTheError`, dan `TestTestPostgresFailures` di-skip di Mac dan hanya diuji di CI. Konfigurasi server lokal (`pg_hba.conf`) sengaja tidak diubah.
- **B2–B6, macOS (22 November 2026):** dijalankan Claude tanpa DevTools: `EXTRA_TAGS=mcp wails3 dev` menyalakan server MCP Wails di 127.0.0.1:9099, lalu `js_eval` meng-import modul binding TS dari Vite dan memanggilnya di WKWebView. Jalurnya sama dengan yang nanti dipakai UI (binding → `/wails/runtime` → `MarshalError`), tetapi tidak ada yang diklik manual. Biner ber-tag `mcp` sudah dihapus dari `bin/`.
- **B7, macOS (22 November 2026):** saat biner polos dijalankan dari terminal, dialog error muncul di belakang jendela lain karena aplikasinya tidak diaktifkan. Diluncurkan sebagai `.app` (`open`), dialog muncul paling depan. Tidak perlu tindakan.
